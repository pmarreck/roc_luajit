## 1. Pipeline and the integration point

```text
checked modules
  ├─ .lss  (default): Monotype → Lifted → Solved → Lambda Mono decisions → direct LIR
  └─ .boxy (--specialize=no): checked CIR → boxy LIR
        ↓  finishLoweredOutput
  procedure passes (TRMC, inline, tag fusion, scalarize, loop append, range, box reuse)
  ReturnSlot / StrAppend / TagReachability / ReachableProcs
        ↓  Arc.insert                     ← ARC: explicit incref/decref
  ReachableProcs, ImmortalLocals.elide, comptime value guards, ROC_LIR_DUMP
        ↓
  LoweredProgram { lir_result: Program.Result, main_proc, target_usize, ... }
        ↓
  dev | llvm | wasm | LIR interpreter (via LirImage) | proposed: Lua emitter
```

- Strategy fork: `lowerCheckedModulesToLir`, `src/lir/checked_pipeline.zig:1232`, branch at `:1238`. Enum `SpecializationStrategy { lss, boxy }` at `src/base/SpecializationStrategy.zig:6`; CLI `--specialize=yes|no` parsed at `src/cli/cli_args.zig:223`.
- Both strategies converge on the private `finishLoweredOutput`, `checked_pipeline.zig:1617`. Pass order: `ProcPasses` phases `:1639-1664` (TRMC must precede ARC, `:1639`), then `ReturnSlot`/`StrAppend`/`TagReachability` `:1666-1669`, reachability `:1671-1682`, **ARC `Arc.insert` at `:1705`** (defined `src/lir/arc.zig:511`), post-ARC reachability `:1717-1727`, `ImmortalLocals.elide` `:1731`, value guards `:1733`, `LirDump.run` `:1735`.
- In Debug builds ARC runs the independent certifier (`arc_certify.certifyStoreOrPanic`, `src/lir/arc.zig:670-684`).
- Output object: `LoweredProgram`, `checked_pipeline.zig:1118`; `Program.Result` (`store: LirStore`, `layouts: layout.Store`, `root_procs`, `root_metadata`, boxy tables), `src/lir/program.zig:622`.
- CLI lowering entry: `lowerCheckedSourceToLir`, `src/cli/main.zig:12898`, policy from `checkedRuntimeLoweringConfig` `:12859`.

**Integration point decision: ARC-complete LIR, consumed like every other backend.** The only supported API returns post-ARC LIR: `finishLoweredOutput` always calls `Arc.insert`, and pre-ARC `generateConsumerLir` is private (`checked_pipeline.zig:1527-1535`). `design.md:14-19,9604-9609` makes "backends receive ARC-complete LIR" the stated contract. SPEC §6's "consume IR before ARC insertion" would require reassembling a private pass sequence outside `finishLoweredOutput`, skipping `ImmortalLocals` and the certifier. That is the kind of reconstruction AGENTS.md forbids, so it is not proposed. See §4 for why post-ARC LIR is also the *better* input for LuaJIT.

The emitter reads `Program.Result` in-process (as the dev and LLVM backends do), not a serialized `LirImage`. `LirImage` (`src/lir/lir_image.zig:1-7,1018`) exists for the interpreter shim's shared-memory transport and adds nothing a Lua emitter needs. *Decision open for review*: whether the emitter should instead read a `LirImage` so it can live out of process.

Control-flow mapping (*measured* on LuaJIT 2.1.1785763465): LuaJIT supports `goto`, so `join`/`jump` become labels and gotos with all frame locals declared at function entry. **Conflict with SPEC wording**: SPEC says "Lua 5.1-compatible source", but `goto` is a Lua 5.2 feature that LuaJIT 2.1 accepts. Staying strictly within Lua 5.1 would force a `while`-plus-state-variable dispatcher on every join. **Decided (BDFN, 2026-09-30):** the output is "LuaJIT 2.1 source", meaning Lua 5.1 plus LuaJIT's documented extensions (`goto`, `ffi`, `bit`, LL/ULL literals).

LuaJIT limits that must be handled explicitly from `frame_locals` and never discovered at runtime: 200 locals per function, 60 upvalues, and bounded Lua call depth for non-tail recursion (native Roc uses a 64 MiB stack, `--stack 67108864` in the build command). When `frame_locals` exceeds the local limit, the frame spills to a register table. That rule keys only on the explicit count.

## 4. ARC, ownership and the GC question

### Facts

- ARC runs last, over ownership-neutral LIR, and emits `incref`/`decref`/`decref_if_initialized`/`free`, each carrying the concrete helper (`RcHelper`, `LIR.zig:678-701`; `layout.RcHelper` = `rc_helper.HelperKey`, `src/layout/rc_helper.zig:72-165`). Contract: `design.md:14957-15015`.
- Refcounted layouts: str, list, list_of_zst, box, erased_box, erased_callable (`src/layout/layout.zig:896-911`). Structs, tag unions and closures are not refcounted themselves; their children are.
- **Runtime uniqueness checks.** Ops flagged `may_runtime_uniqueness_check_args` (`LowLevel.zig:649-654`) read the count to choose in-place versus copy. Examples: `list_reserve`, `list_set`, `list_concat`, `list_append_*`, `str_concat`, `str_reserve`, `box_prepare_update` (rows `LowLevel.zig:863-1061`). Unflagged count readers: `list_map_can_reuse`, `list_slack_unique`, `list_owned_unique`.
- `assign_low_level.unique_args` is a *static* ARC proof that lets a consumer skip the check. "The runtime check is always sound, so a zero mask reproduces fully checked behavior" (`LIR.zig:1271-1281`). `reuse_unique` on `assign_packed_erased_fn` is the same kind of proof (`LIR.zig:1150-1162`).
- Several ops write **unchecked** and rely on a preceding truthful check: `list_append_unsafe`, `list_set_in_place_unsafe`, `list_append_range_within_unsafe`, `list_map_*_unsafe` (`LowLevel.zig:953-992`). `List.append` is itself `list_append_unsafe(List.reserve(list, 1), item)` (`src/build/roc/Builtin.roc:4113-4116`, verified).
- Allocation initializes the count to 1 (`src/builtins/utils.zig:911`, verified). Static data uses count 0, which is never unique (`utils.zig:284,763-775`).
- The builtins already contain a no-RC mode: `RC_TYPE = .none` makes `rcUnique` return false (`utils.zig:320-326,763-775`). It is not selected anywhere at this revision.
- No Roc-visible API exposes counts. Counts reach hosts through `roc_dealloc` on final release and erased-callable `on_drop` on final release (`src/builtins/host_abi.zig:145-177`, `src/builtins/erased_callable.zig:46-60,246-267`).
- The LIR interpreter keeps real counts in memory and answers checks from them (`interpreter.zig:3239-3360`, checks at `:4823`, `:6589-6600`, `:9947`).
- Pre-ARC reuse passes (`box_reuse.zig`, `return_slot.zig`, `trmc.zig`, `loop_append_promote.zig`) do not assume ownership. They either write into fresh allocations (TRMC) or route through a runtime check-or-copy op (`box_prepare_update`, `list_slack_unique`/`list_owned_unique` at loop entry).

### Three candidate policies

| Policy | Sound? | Complexity |
|---|---|---|
| A. incref/decref no-ops, checks still read a stored count | **Unsound.** Every allocation starts at 1 and never rises, so shared lists pass the check and `*_unsafe` ops write through aliases. | n/a |
| B. incref/decref no-ops, every runtime check answers "not unique" (static `unique_args`/`reuse_unique` honored) | Sound by the `LIR.zig:1271-1281` contract, subject to the representation caveat below. | Accumulation loops become quadratic. |
| C. Follow every RC statement literally with a count stored on refcounted Lua objects; LuaJIT's GC reclaims memory | Sound; identical decisions to native. | Native complexity. |

*Measured* with `luajit_backend/probes/uniqueness_policy.lua`, a model of `List.reserve` plus `list_append_unsafe` on LuaJIT 2.1, best of 5, CPU time:

```text
counted  n=250000..2000000  per-doubling ratio 1.71, 1.34, 2.10   (2M appends: 0.011s)
never    n=4000..32000      per-doubling ratio 3.34, 7.11, 5.51   (32k appends: 2.58s)
```

The model shows what happens *where the check actually runs at runtime*. Real LIR narrows where that is (*measured*, `ROC_LIR_DUMP` of `luajit_backend/probes/lir/*.roc` with the Debug `roc` built at this revision):

- A simple `while` loop appending to a local list gets `list_reserve(...) unique=0x1`. ARC proved it statically, so policy B stays linear there (`probes/lir/append_loop.roc`).
- These sites keep a runtime check with no static proof (`probes/lir/append_variants.roc`, one dump):
  - `List.append` called as a procedure: `Builtin.List.append` has `list_reserve` with no mask, and the masked copy appears only where it is inlined.
  - The Dict insert internals: `dict_ensure_capacity` and `dict_insert_new_data` call `list_reserve`, and `dict_place_and_shift_up` calls `list_set`.
  - A `List.set` loop over a caller-supplied list.
  - `loop_append_promote` versions a loop on runtime `list_slack_unique`/`list_owned_unique` probes.

Under policy B, each of those sites copies the whole backing list, so `Dict.insert` loops, `List.set` loops over parameters, and appends through non-inlined calls become quadratic. That hits SPEC §42's failure criterion ("every meaningful structured update requires pathological copying").

### Decision: policy C (approved by BDFN, 2026-09-30)

Follow ARC statements mechanically, exactly as AGENTS.md requires:

- Refcounted values become Lua objects carrying a count. `incref n` adds n. `decref` subtracts and, on reaching zero, runs the helper plan's child releases (`rc_helper.zig:117-165`) so nested counts stay exact. `free` and a zero count release nothing else: the GC reclaims storage. Static data carries the never-unique marker.
- Runtime checks read the count. `unique_args`/`reuse_unique` bits skip the check exactly as other backends do.
- The emitter never elides, merges or invents RC operations and never inspects ARC internals. A later optimization may only follow explicit LIR data, such as a future upstream "RC-free" mode.

This resolves the SPEC/upstream tension empirically. SPEC §6's no-op path is only sound as policy B, and B fails SPEC's own performance criterion. SPEC §6 anticipated this: ownership information "may still be extremely valuable even when LuaJIT handles lifetime management".

Representation caveat (from the ARC survey, applies to B and C): LIR by-value aggregates (`struct_`, `tag_union`) may be shared Lua tables *only if no LIR statement mutates them in place*. At this revision the only in-place writes are `store_struct`/`store_tag`/`ptr_store` through `ptr` layouts and the builtins' own buffer writes. M2 must pin this with an alias test before sharing aggregate tables.

Open costs of C to measure in M1/M2: RC traffic in hot loops (borrow inference already removes most, `design.md:14957-14980`), and host-visible `on_drop` timing. Under C that timing matches native final release, so no `__gc` finalizer is needed for correctness.

## 5. Representation metadata available to the backend

- Well-known layouts: `layout.Idx` bool=0 … dec=14, opaque_ptr=15, zst=16, SIMD 17-24 (`src/layout/layout.zig:139-196`). Tags: scalar, box, box_of_zst, list, list_of_zst, struct_, closure, erased_callable, zst, tag_union, ptr, erased_box (`:18-32`).
- Struct fields: committed sorted order (alignment, then semantic index); `RefOp.field.field_idx` is the *semantic* index (`field_order.zig:1-15`, `layout.zig:218-243`, `layout/store.zig:2577,2586`). The Lua emitter should use semantic indices as table slots and ignore byte offsets, except for nominal declared-order records whose padding fields are marked `is_padding` (`layout.zig:236`).
- Tag unions: `TagUnionData` (`layout.zig:353-368`); LIR carries both `variant_index` and `discriminant` on every tag operation (`LIR.zig:918-927,1310-1330`). *Open*: whether the two ever differ. The emitter will use `discriminant` for switches and `variant_index` for payload layout lookup, as the statements state, never assuming equality.
- `ptr` layouts exist only for TRMC, destination-passing and box update (`layout.zig:28-30`; ops `ptr_alloca`, `box_alloc_zeroed`, `ptr_store`, `ptr_load`, `ptr_cast`, `LowLevel.zig:600`). In Lua a `ptr` becomes an explicit (container, slot) reference. This is M3/M4 work.
- Integer arithmetic families are distinct ops: `_wrap`, `_crash_on_overflow`, `_overflows` (predicate), `_proven_cannot_overflow` (`LowLevel.zig:139-181`, `design.md:14693-14830`). Plain source arithmetic crashes on overflow at every opt level.

### Static data (needed from M1)

Compile-time evaluation runs first, and its results reach runtime LIR as `assign_literal` with `static_data sN` (*measured*: in `probes/lir/scalars.roc`, the whole `Str.inspect(pick(add_one(41) > 0, …))` folds to one `literal static_data s1` of layout `str` passed to `Echo.line!`). Each slot is a `StaticDataValue` (`src/lir/program.zig:550`) with a `layout_idx` and either:
- an `initializer` procedure flagged `is_static_initializer` (`LIR.zig:1597`), whose exact post-layout construction can run at Lua module load, or
- completed frozen data (`LoweredProgram.frozen_static_data`, `checked_pipeline.zig:1123`; `FrozenStaticData` at `program.zig:92`), stored as target bytes plus relocations.

The emitter therefore needs a layout-driven decoder from frozen bytes to Lua values, or must run the initializer. Which of the two applies to each slot is explicit data. Static values are never unique (native count 0, `utils.zig:284`), so under policy C they carry the never-unique marker.

### Numerics (the M1 blocker to plan around)

Unannotated literals default to `Dec` (`layout.zig:190`, and eval tests such as `if (1 == 1) 42 else 99` expect `"42.0"`). `Dec` is 128-bit fixed point implemented entirely in Zig builtins (`src/builtins/dec.zig`). **So the first M1 differential cases already need exact i128 arithmetic plus a faithful `dec_to_str`, not only doubles.** Proposed exact mapping:

| Roc | LuaJIT |
|---|---|
| Bool | `true`/`false` (Bool tag union read via its committed layout) |
| U8, I8, U16, I16, U32, I32 | Lua number (all exactly representable) with explicit range checks per op family |
| U64, I64 | A Lua number when -2^53 < v < 2^53 (U64: v >= 0), otherwise `uint64_t`/`int64_t` cdata; any value may arrive in either form, and results are numbers whenever they fit (§10, 2026-10-01 "Mixed I64/U64"). LuaJIT wraps cdata mod 2^64 (*measured*: `INT64_MAX+1 = INT64_MIN`), so `_crash_on_overflow`/`_overflows` need explicit checks. |
| U128, I128, Dec | *Implemented:* an immutable table of eight 16-bit limbs, least significant first (`src/backend/lua/wide.lua`, `int128.lua`), with ops ported from `src/builtins/dec.zig` |
| F32 | Lua number rounded through `float` cdata after every op |
| F64 | Lua number |
| Str | Lua string for M1; revisit in M5 (in-place `str_concat` needs a mutable buffer) |

`f64_to_str`/`f32_to_str` must match Roc's shortest round-trip formatter (`vendor/ryu.zig`), not Lua's `%.17g`. BDFN pointed to `../BLIP` and `../blip_mp` as possible sources for exact wide-integer algorithms; queued in PLAN.md for M6. Roc has no arbitrary-precision type, so the need is 128-bit ops plus 256-bit intermediates for `Dec` multiply and divide.

## 6. Calling convention, platform boundary, provenance

- Direct calls: `assign_call { proc, args }`; ownership already explicit through RC statements and each proc's `rc_borrowed_params`/`rc_ret_*` (`LIR.zig:1615-1617`). In Lua, one generated local function per `LirProcSpecId`. Self-tail sites are already rewritten into loops by TRMC/TCE (`tail_transform`, `LIR.zig:1027-1031,1607`); other calls in return position may become Lua tail calls only where the LIR is `assign_call` immediately followed by `ret` of that target with no intervening RC statement.
- Erased callables: `assign_packed_erased_fn`/`assign_call_erased` (`LIR.zig:1110-1165`); a Lua closure-object representation is M4.
- Hosted functions: `LirProcSpec.hosted = { symbol, dispatch_index }` (`src/lir/hosted.zig:9-14`). - Roots: `RootMetadata { order, kind, abi, exposure, test_plan }` (`src/lir/root_metadata.zig:42-54`) parallel to `root_procs`.
- Host services: `RocOps` (alloc/dealloc/realloc/dbg/expect_failed/crashed/hosted_fns), `host_abi.zig:145-177`. In Lua: alloc/dealloc disappear (GC); `crashed` becomes a structured `error({roc_panic=...}, 0)` caught by the runner; dbg/expect become runtime callbacks.
- **Minimal stdout platform for M1: the echo platform**, `src/echo_platform/platform/main.roc` (provides `roc_main`, hosted `roc_echo_line: Echo.line! : Str => {}`). - Provenance: `StmtOrigin { loc, region, inline_scope, kind }` per statement (`LIR.zig:222-293`), `SourceLoc { file, line, column }` (`src/base/source_loc.zig:13-28`), accessors `stmtLoc`/`stmtOrigin`/`procLoc`/`sourceFileName` (`LirStore.zig:1058-1176`). ARC statements carry no location. Debug-mode Lua comments and a `.rocmap` sidecar can be generated from these columns alone.

## 7. Oracle and differential runner design

### Reusable fixtures

- Eval corpus: `src/eval/test/eval_tests.zig` aggregates 16 files, about 2,409 cases (static count, *inferred*): 2,099 `inspect_str`, 66 `crash`, 35 `allocations_at_most`, 71 comptime float bits, 84 problem cases. Programs are wrapped as `main = || Str.inspect(expr)` (`src/eval/inspected.zig:2535`). The rendering itself therefore runs inside the backend under test, not in the harness.
- CLI echo suite (exact stdout, `src/cli/test/parallel_cli_runner.zig`) and fx io specs (`src/cli/test/fx_test_specs.zig`, 122 stdin/stdout/stderr specs) for platform effects in M1/M7.
- Snapshot `# OUTPUT` sections are interpreter output frozen in the repo. They are not an independent oracle and are used only as extra corpus.

### Existing runner and its loopholes (*verified in source*)

`run-test-eval` (`src/eval/test/parallel_runner.zig`) compares each backend with the expected string and with the first passing backend (`:1427-1435`). A backend that is `not_implemented` or skipped is silently left out of the verdict, and the case still reports PASS (`:1398-1401`, `:910-955`). Adding Lua there as a fifth column would inherit that. The lambda-mono differential runner is the better model: it counts `unsupported` by reason and fails when nothing executed (`src/eval/test/lambda_mono_differential_runner.zig:182-197,578-625`).

### `luajit_differential` runner (implemented 2026-09-30)

`src/eval/test/luajit_differential_runner.zig`, step `zig build run-test-luajit-differential` (not part of upstream MiniCI; `./test-all` runs it through `luajit_backend/tests/run`).

1. Each eval-corpus case is compiled once with `compileInspectedProgram`. Both sides consume that one lowering.
2. **Oracle**: `lirInterpreterTranscript`. It is cross-checked against the corpus's static `inspect_str`, and a mismatch there is an `oracle_error`, never a pass.
3. **Subject**: `backend.lua.emitProgram` writes a self-contained Lua file (runtime embedded) into `TMPDIR`. A separate `luajit` process (`ROC_LUAJIT_BIN`, default `luajit`) runs it. The protocol: the `Str` result goes to stdout with exit 0; a Roc crash writes its message to stderr with exit 3; any other Lua error exits 1.
4. Verdicts: `pass`, `diverged` (output bytes, or crash status and message), `lua_error`, `unsupported(reason)`, `oracle_error`, `compile_skip`, `child_failed`. The run fails on any divergence, Lua error, oracle error or child failure; on zero passes; or when unsupported cases exceed `max-unsupported=N`. The committed ratchet is in `luajit_backend/tests/unsupported_ratchet`.
5. The negative control is `mutate=int-literals expect-divergence`, which passes only if the mutated emitter diverges.
6. Each result records the SHA-256 of the emitted Lua (shown with `--verbose` and in every divergence).
7. Independence: `src/backend/structural_test.zig` forbids the emitter from naming `eval`/`LirInterpreter`, and requires its `.incref =>`/`.decref =>`/`.decref_if_initialized =>` arms, like every other backend.

Measured on 2026-09-30 (8 threads, 16-core affinity), across 2,291 cases (problem-only cases excluded): 246 agreed, 0 diverged, 0 Lua errors, 0 oracle errors, 2,045 unsupported. The largest gaps are `dec_literal` (514), `assign_list` (242), tag construction (175), non-ZST structs (123), f64/f32 literals (197) and `str_inspect` (100). The negative control diverged as required (oracle `6`, mutant `8`).

After the I128/U128/Dec slice (same date and setup): 360 agreed, 0 diverged, 0 Lua errors, 1,931 unsupported. The wide runtime is checked three ways. `luajit-numeric-vectors` (built ReleaseSafe, because Zig 0.16.0 Debug misreports some `@mulWithOverflow(i128)` overflows) writes 32,893 vectors from upstream's `RocDec` builtins and native u256 arithmetic, and `int128_vectors.lua` replays them. Mutants of the Lua runtime (trailing-zero formatting, division overflow) fail it. One mutant survives by proof: replacing the reciprocal R = floor(2^315/10^18) with R - 1 in `dec_mul` is equivalent over the whole input domain (argument in `int128.lua`). A second negative control, `mutate=dec-literals`, adds 10^-18 to every Dec literal and must diverge.

#### M1 representation note on Str and RC

Policy C (§4) executes every RC statement. In M1, `Str` is an immutable Lua string, and no operation in the supported subset performs a uniqueness check. So the runtime's `incref_str`/`decref_str`/`free_str` helpers have no count to maintain. The emitter still emits every RC statement as a helper call and never decides to skip one. When in-place Str operations enter the subset (M5), `Str` becomes a counted representation and those helpers maintain real counts.

Platform-effect cases (M1 stdout demo, later M7) use the same verdicts over stdout/stderr bytes and exit status, with the native echo host as oracle.

- Zig's InternPool packs a thread id into each 32-bit item index, so each thread owns 2^(30 − ceil(log2 threads)) items: 33.5M at 17–32 threads, 16.7M at 33–64, 8.4M at 65–128.
- Release compilers guard that limit only with a debug assert. A ReleaseSafe compiler with debug info panics at `InternPool.zig:7044` (`put` → `wrap`), reached from `Sema.coerceArrayLike` (`Sema.zig:29922`).

That coerces an `@embedFile` `[N:0]u8` to `[N]u8` element by element, interning one `usize` per index. The two blobs total about 27.2M items on the main thread.
- So up to 32 CPUs build, and 33 or more crash. Which CPUs are used does not matter, and `zig build-exe -jN` reproduces it on any machine.

- Earlier reports of the same failure for string indices are ziglang/zig #22867 and #25297, fixed by PR #25464 for 0.15.2. Item indices keep the limit.
- The draft report, patch and repros are in `<local scratch>/roc_luajit-5f5f96c03a7f/zig-segv/`. Filing upstream is BDFN's decision.

## 10. Decision log

Decisions taken without a round trip to BDFN under his standing directive (PLAN.md): prefer parity plus speed, else parity. Each entry names the options considered.

- **2026-09-30. Wide integers are 8×16-bit limb tables** (options: two int64 cdata halves, or 16-bit limbs in Lua numbers). Limbs keep every partial product below 2^53, so plain doubles stay exact with no cdata allocation per step. BDFN chose "correctness first" and a pure-LuaJIT port; revisit with benchmarks.
- **2026-09-30. Floats will port Roc's `src/builtins/float_math`** instead of calling LuaJIT's `math.*` (libm). Every reachable Roc path uses that code (see PLAN.md, transcendental provenance), so a port is the only route to bit parity.
- **2026-09-30. SIMD uses an FFI `roc_v128` union** with lane loops, not a native shim (BDFN agreed; measure).
- **2026-09-30. Roc-level runtime errors keep Roc's text and status.** Every crash the runtime raises uses the exact message upstream's interpreter or builtins produce (taken from `lir/checked_arithmetic.zig` or `builtins/dec.zig` at emit time where possible), and the program exits with the crash status, never a Lua error.
- **2026-09-30. Aggregate representation** (options: FFI structs mirroring native byte layouts, or Lua tables). Structs are Lua arrays indexed by semantic field index + 1; tag unions are `{discriminant, payload}`; boxes are counted cells `{rc, v}`. Values are immutable after construction, so references are shared freely. Tables give parity with no byte-layout emulation; FFI layouts remain an optimization candidate once benchmarks exist. RC helpers are generated per helper key from upstream's `layout/rc_helper.zig` plans, so the backend follows ARC's statements without deciding anything itself.
- **2026-09-30. Lists port `builtins/list.zig` exactly** (options: plain Lua arrays with copy-on-write, or a faithful port). `List.capacity` is a public builtin and in-place updates depend on refcounts, so lists keep the builtin's model: an allocation `{rc, cnt, slots}` plus an immutable header `{a, o, n, c, s}` covering seamless slices, capacity growth by native element width, and static data (rc 0). `src/backend/lua/list.lua` mirrors each builtin function and each interpreter case.
- **2026-09-30. Str stays an immutable Lua string** (options: model RocStr's small/heap/slice representation and capacity, or Lua strings). Str has no capacity getter, so content is all Roc code can observe, with one exception: `Str.to_utf8` on a heap string (more than 23 bytes) shares its allocation, so the list's capacity equals the string's. The backend returns an exact-capacity list instead. No test in the corpus observes that capacity; revisit by modelling RocStr if one does.
- **2026-09-30. Floats are Lua numbers; F32 rounds after every operation** (options: FFI float cdata, or doubles rounded through a float store). Rounding the exact double result of + - * / sqrt to binary32 equals one correctly rounded binary32 operation (53 >= 2*24+2), so F32 arithmetic is exact without cdata. Formatting runs Ryu's digit-removal loop on exact big integers instead of its 128-bit tables (LuaJIT has no 128-bit multiply); 30,921 vectors from upstream's formatter agree. Integer and Dec to float conversions round the exact rational once (round-half-even), avoiding the double rounding an int -> double -> float path would introduce.
- **2026-09-30. NaNs are canonicalized on entry.** LuaJIT NaN-tags its values, so a non-canonical NaN read from FFI memory can turn into a non-number. `from_bits` maps every NaN pattern to LuaJIT's NaN and `to_bits` returns Roc's canonical quiet NaN. Roc normalizes NaN bits itself and prints every NaN as `nan`, so no program can observe the difference.
- **2026-10-01. `List.sort_with` ports fluxsort comparison for comparison** (options: any stable sort, or a faithful port of `builtins/sort.zig`). A stable sort gives the same output only for a total preorder; a comparator that contradicts itself, crashes or prints with `dbg` exposes the exact comparison sequence. `src/backend/lua/sort.lua` maps byte pointers to indices in one flat table, so pointer arithmetic and comparisons carry over in element units. 6,140 vectors replay upstream's `fluxsort` under total, duplicate-heavy and hostile comparators and match its full comparison trace (call count, rolling hash of the operand pairs, output order); ten of eleven mutants fail them. The surviving mutant is in `trinity_rotation`, which `listSortWith` cannot reach: every fluxsort path passes `swap_len >= len`, and the vectors confirm no call. One divergence is inherent: `median_of_cube_root` (partitions over 2048 elements) derives its sample offset from a stack address, so native Roc itself is not deterministic there. The port uses offset 0, and lists over 2048 are checked for output order under total preorders only.
- **2026-10-01. Number parsing ports the token grammars and computes exact values** (options: hand-rolled `tonumber`-style parsing, or ports of `builtins/num.zig`, `builtins/decimal_parse.zig` and the acceptance rules of `vendor/parse_float`). `tonumber` accepts a different grammar (no `_` separators, no `1e3` integers, different hex rules) and its float rounding is libc's. `src/backend/lua/numparse.lua` mirrors each scanner and range check; floats come from the exact rational the token denotes, rounded once with subnormals (`float.lua` `round_scaled`), which is what parseFloat's Eisel-Lemire and slow paths compute. Clinger's fast path (one double operation, as `convertFast` does) covers short significands with small exponents. 328,120 vectors from upstream's parsers (edge strings, random grammar soup, random `{e}`-formatted floats, hex floats, long digit strings near halfway points) agree on both the Str and List(U8) entry points.
- **2026-10-01. `wide.lua` division is Knuth's Algorithm D** (options: keep bit-serial restoring division, or schoolbook long division in base 2^16). Parsing long float literals made the O(bits) loop with one allocation per bit the bottleneck (1.4 ms per parse). Algorithm D keeps every estimate and partial product below 2^53. All 845,792 numeric vectors agree, and 4/4 mutants are caught, including the rarely taken add-back step (44 failures).
- **2026-10-01. `Str.from_utf8` resolves its Result layout as the interpreter does** (`str_from_utf8` in `eval/interpreter.zig`): Ok is the variant whose payload (after a single-field wrapper) is Str, and the BadUtf8 `{ index : U64, problem }` record sits either directly in Err or as a variant of an open error union. The emitter performs the same resolution at emit time and refuses layouts outside it. As with `Str.to_utf8`, the resulting Lua string shares nothing with the list, so the list's refcount does not carry the extra reference `fromUtf8` adds; only `List.capacity`-style uniqueness observations could tell. 8,066 vectors from `str.fromUtf8`/`fromUtf8Lossy` agree; 4/4 mutants are caught.
- **2026-10-01. Dict/Set hashing ports `builtins/hash.zig` with a fixed pseudo seed** (options: random per run, or a constant). Every hasher write is wyhash over `domain || le64(len) || bytes`, computed on uint64 cdata with a 64x64->128 multiply from 32-bit halves; 52,000 upstream vectors agree, 4/4 mutants caught. `dictPseudoSeed` is a function's address with the top bit set, so native Roc's seed changes with ASLR and no correct program can depend on it; the backend uses the constant `0x8000000000005eed`, which keeps the marker bit and makes runs reproducible.
- **2026-10-01. F32/F64 transcendentals port `builtins/float_math`; F64 `log` uses the C library** (options: LuaJIT's `math.*` (libm), or ports). Roc evaluates sin, cos, tan, asin, acos, atan, atan2 and pow with its own Zig code (`float_math/f64.zig` over the fdlibm-derived `trig.zig`, `rem_pio2*.zig`, Zig std asin/acos/atan; `float_math/f32.zig` with exact fixed-point 2/pi reduction), so libm results would differ in the last bit. `src/backend/lua/fmath.lua` repeats every binary64 operation in order; F32 code rounds each operation through `F.f32`, and LuaJIT does not contract multiply-adds. `rem_pio2.zig` folds `3 * pio2_1t` at comptime precision; a vector pins its binary64 value. F64 `log` is `@log` in the interpreter, which resolves to the linked C library's `log`, so native Roc itself depends on the platform libm here; the port calls `math.log`, which is the C library's `log` as well. The vector generator links musl and LuaJIT on this host calls glibc; all 2,048 `log` vectors agree. 157,697 vectors (edge values, values near multiples of pi/2, huge arguments taking the Payne-Hanek path, random bit patterns) agree bit for bit; 8 of 11 mutants fail them. The survivors change a result only on rare inputs (a 1-ulp F32 log coefficient, a branch threshold one high-word ulp away, the third Cody-Waite step).
- **2026-10-01. SIMD ports `builtins/simd.zig` lane for lane over an immutable FFI `roc_v128` union** (as decided on 2026-09-30). Lane kinds are descriptors (width, count, signedness, natural/unsigned/signed field); lanes up to 32 bits compute as exact Lua numbers and 64-bit lanes as uint64/int64 cdata, so every stored value is already in its field's range and nothing depends on FFI truncation of out-of-range numbers. `to_u128_bits`/`from_u128_bits` map the union's 16-bit lanes onto the U128 limb representation, vector constants are emitted through `from_u128_bits`, and the operand kind is chosen as `evalSimd` chooses it (first vector argument, else the result). Load/store/append on `List(U8)` follow `evalSimdLoad/Store/Append` (make-unique unless ARC proved the list unique, reserve 16 then append). 99,300 vectors from `builtins.simd.eval` (every op x every kind Roc exposes, edge-biased lanes) agree; 11/13 mutants are caught and the two survivors are equivalent (`shr_rounded` at count == width yields 0 either way; saturating narrow of 0 yields 0 either way).
- **2026-10-01. SHA-256 and BLAKE3 port `builtins/crypto.zig` with its hashers' buffering** (options: any correct digest implementation, or a structural port). Programs hold incremental hasher states as `List(U8)` in crypto.zig's own serialization, so partial-block buffering (SHA-256 never buffers a whole block; BLAKE3 keeps a full final block until more input arrives) and Zig std Blake3's CV stack (lazy merging, plus the multi-chunk subtree path that pushes a subtree's two child CVs) are observable. `src/backend/lua/crypto.lua` follows them step for step; subtree child CVs are computed recursively, which equals what `compressSubtreeWide` produces for any SIMD degree. Invariant crashes keep crypto.zig's messages. 3,000+ vectors from `builtins.crypto` (one-shot digests and incremental chains across block, chunk and subtree boundaries, every serialized state compared) agree; 9/10 mutants are caught and the survivor (the counter's high word) needs over 2^32 chunks.
- **2026-10-01. String patterns lower to an ordered `if`/`elseif` over `rt.str_match`**, which repeats `LIR.strMatchStep` exactly, including its rule that a delimiter is tried only at the first occurrence of its first byte (a `string.find` of the whole delimiter would accept more). Captures are Lua substrings; the seamless-slice sharing they have in native Roc is not observable through Str. Captured views are read from `rt.cap` immediately on the match edge, so no Lua local is declared inside the branch (Lua forbids a `goto` into a local's scope). Unit checks pin the first-byte rule; replacing it with a full search fails them.
- **2026-10-01. Bytes literals decode records field by field** at the layout's native offsets (by original field index), recursing through nested structs and vectors, because `evalBytesLiteral` copies element storage verbatim.
- **2026-10-01. `roc build --target=luajit` emits one runnable Lua file** (SPEC §3's first form; options: a separate `roc-luajit` driver, or a CLI target). `rocBuildLuajit` (`src/cli/main.zig`) lowers to ARC-complete LIR exactly as the embedded (interpreter) build does, emits a platform-mode chunk (LuaEmitter `Input.entrypoints`) and wraps it in the platform's LuaJIT host (`src/backend/lua/LuaHost.zig`). The native runtime's post-crash backtrace has no LuaJIT counterpart and is the one stderr difference.

LuaJIT output has no native optimization level; the speed configuration added the "dbg in optimized build" warning (failing the build status) and, in Debug compilers, reached an upstream ARC invariant panic that the dev lowering avoids. Each program sizes its work by its argument count and declares its intended complexity and base scale. `./bm` checks LuaJIT output against the native `--opt=speed` build (a benchmark of wrong output is void), times LuaJIT at 1x/2x/4x scale with hyperfine (`-N`, CPU time = user + system), gates growth (O(n): each doubling under x3; O(1): 4x input under x1.5) and fails on a CPU-time change beyond ±25% from this machine's previous entry in either direction (rerunning accepts it). - **2026-10-01. Emitted code is shaped for LuaJIT's trace recorder** (profiling `./bm` with `-jv`/`-jp=v` showed dict_ops 55% interpreted and 4% compiled, with almost every trace aborted). Four causes, each fixed at its source and pinned by `luajit_backend/tests/emitted_layout` or a lint:
  1. *Frame size.* Every procedure declared all its LIR locals (up to 189), and a trace aborts past 250 stack slots across inlined frames ("trace too deep"). `assignSlots` now gives LIR locals Lua slots by backward liveness over the emitter's statement graph (join → remainder, jump → join body, reads and definitions from `lir.BodyClone.forEachStmtRead/Def`), an interference graph (each definition against everything live after it and the statement's other operands) and greedy coloring, parameters first. A 240-step chain went from 189 declared locals and a spill table to 3.
  2. *Layout.* Segments were emitted from a LIFO queue, so merge points could precede their predecessors. They are now laid out in reverse postorder, so only back edges jump backward.
  3. *Loops.* A backward `goto` compiles to a plain JMP, which LuaJIT never hot-counts: a goto loop of 10^8 iterations ran interpreted (0.83 s vs 0.16 s as `while`), and a tail-recursive Roc loop produced no trace at all. Each natural loop (back-edge target plus the segments that reach the back edge's source without passing it) is now a `while true do ... end` block right after the header's label, holding every segment of the loop, nested loops inside. Back edges pass its LOOP bytecode, which LuaJIT counts and closes traces on, and the block contains the whole body because a root trace aborts on bytecode outside it ("leaving loop"). Loops entered other than through their header are refused. A 1,000,000-iteration tail loop went from 0.199 s to 0.037 s.
  4. *Tail calls in the runtime.* LuaJIT counts each tail call against the trace's loop-unroll limit (15), and a helper whose last act is a tail call to a builtin (`return bit.bxor(hi, lo)`) returns from a non-Lua frame, which a root trace cannot record. Such helpers were blacklisted, and every loop trace calling a blacklisted helper aborted with it. `luajit_backend/scripts/tail_calls.lua` finds tail calls in the loaded runtime's bytecode, resolves each callee through the instruction that loaded it and classifies it as single-valued (only RET0/RET1, or a listed builtin), multi-valued or unknown. The 381 single-valued sites became `return (f(...))`, and the suite runs the script with `--check`. Raising `loopunroll` instead was measured and rejected: dict_ops took 0.16 s at 100 and 200 but 0.70 s at 150 and 0.72 s at 300.

- **2026-10-01. - **2026-10-01. Mixed I64/U64** (BDFN chose this over keeping cdata and over an opt-in flag).
